# 47DR 驱动包

建议先阅读面向实际联调的[驱动使用指南](dr47_user_guide.md)，其中包含安装、
网络准备、板卡发现、波形播放、同步触发和验收预期。

完整的函数、参数、返回值、CLI 和双板卡端到端示例见
[API 参考](dr47_api.md)。

构建并安装 wheel：

```bash
cd software/dr47
python -m pip wheel --no-deps -w dist .
python -m pip install dist/47dr_driver-*.whl
```

用户进程直接通过 UDP 控制单块板卡：

```python
from dr47 import Dr47Device

with Dr47Device(
    ip="192.168.1.128",
    port=1234,
    udp_interface="enp225s0f0",
    udp_source_ip="192.168.1.10",
) as device:
    device.download_qc_wave_seq("xy", 1, wave, sequence)
    # Public frequency arguments are GHz.  RFCTRL2 conversion is internal.
    device.set_xy_nco_frequency(1, 1.0)
    device.set_qc_on_off("xy", 1, "on")
    device.arm()
    device.trigger()  # local software trigger; does not require XS20 SYNC
    # device.abort_mute()  # whole-board stop/mute
```

`Dr47Device.set_xy_nco_frequency()` and `apply_rfdc_config(nco_ghz=...)` use
GHz.  The low-level `rfctrl2_*` methods remain protocol helpers and use the
integer Hz fields required by RFCTRL2.  The RFDC input stream is 0.4 GHz
(400 MS/s), so a carrier above 0.2 GHz should normally be put in the NCO and
the uploaded IQ waveform kept as a baseband envelope.

## SYNC and Trigger wiring

The three SMP connectors have fixed roles. Type-C internal synchronization is
not used by this driver or bitstream.

| Connector | Direction/function | Driver API |
| --- | --- | --- |
| XS20 | Dedicated SYNC link. A master drives one SYNC pulse; a slave receives it. | `sync()` on an external-mode master |
| XS18 (`TRIG_1`) | Trigger output. | `emit_trigger()` |
| XS19 (`TRIG_2`) | Trigger input. In external mode it is gated until XS20 SYNC is seen. | Physical input only |

`set_sync_mode("external")` is the formal operating mode. A board configured
as `slave` does not accept XS19 Trigger edges until one real rising edge has
arrived on XS20. That one edge is sufficient for the current synchronization
epoch; do not send a second SYNC pulse as part of the Trigger operation.
`sync_seen` and `sync_link_ready` in `device.status().capabilities` report the
gate state.

`bypass_sync()` is an explicit local-run bypass: it marks the
sync gate ready without requiring XS20. It is appropriate for testing a board
with `XS18 -> XS19` physically looped back, but it does not establish timing
alignment with another board and must not be used for a synchronized experiment.

`device.trigger()` and `device.emit_trigger()` are intentionally different:

- `trigger()` sends a UDP local software trigger and starts this board's local
  playback path. It does not create a pulse on XS18.
- `emit_trigger()` creates one pulse on XS18. It does not directly start local
  playback. The pulse must reach an XS19 input through a physical cable.

### External-SYNC slave with external Trigger input

Connect the timing source through an SMA-to-SMP cable to XS20, connect the
Trigger source to XS19, and configure the board before arming it. The waveform
sequence must contain a Trigger-wait instruction, such as the sequence created
by the public `make_trigger_sequence()` helper in `dr47.sequence`.

```python
from dr47 import Dr47Device, make_trigger_sequence

sample_count = 48  # Must match the uploaded waveform length.

with Dr47Device(
    ip="169.254.32.1",
    udp_interface="enp225s0f1",
    udp_source_ip="169.254.250.11",
) as device:
    device.set_sync_role("slave")
    device.set_sync_mode("external")

    # Configure and upload CH1 before arming; iq is an (N, 2) or (2, N) int16 IQ array.
    device.download_qc_wave_seq("xy", 1, iq, make_trigger_sequence(sample_count))
    device.set_xy_nco_frequency(1, 1.5)  # GHz
    device.set_qc_on_off("xy", 1, "on")
    device.arm(channel_mask=0x01)

    # Wait for exactly one physical XS20 SYNC rising edge. Then every XS19
    # rising edge starts one waveform playback. Do not call trigger() here.
    print(device.status().capabilities)
```

### Single-board XS18 -> XS19 Trigger-loopback test

Connect XS18 directly to XS19 with the correct SMA-to-SMP cable and leave XS20
unconnected. This verifies the real output connector, cable and input connector
without pretending that an external SYNC source exists.

```python
from dr47 import Dr47Device, make_trigger_sequence

sample_count = 48  # Must match the uploaded waveform length.

with Dr47Device(
    ip="169.254.32.1",
    udp_interface="enp225s0f1",
    udp_source_ip="169.254.250.11",
) as device:
    device.set_sync_role("slave")
    device.bypass_sync()  # Local bypass only; no XS20 signal.
    device.download_qc_wave_seq("xy", 1, iq, make_trigger_sequence(sample_count))
    device.set_xy_nco_frequency(1, 1.5)
    device.set_qc_on_off("xy", 1, "on")
    device.arm(channel_mask=0x01)

    device.emit_trigger()  # XS18 pulse -> cable -> XS19 -> one playback
    status = device.status()
    assert status.capabilities.trigger_output_count >= 1
    assert status.capabilities.trigger_accepted_count >= 1
    device.abort_mute()
```

For a two-board arrangement, use `master XS20 -> slave XS20` for SYNC and
`master XS18 -> slave XS19` for Trigger. Set both boards to `external`, then
use `SyncGroup.sync()`. Each call automatically aborts/mutes both players,
emits SYNC, reruns DAC MTS and NCO SYSREF alignment, and waits for matching
alignment epochs. The uploaded waveform is retained, but both boards must be
armed again after a successful sync before calling `trigger()` or
`emit_trigger()`.

逻辑通道固定映射为 `xy 1..4 -> CH1..CH4`、`z 1..2 -> CH5..CH6`、
`ro/ifout 1..2 -> CH7..CH8`。`ri/ifin`、DAQ、demod 和 pump 在当前
bitstream 中没有能力位，调用会抛出 `UnsupportedCapabilityError`。

波形可以是 IQ 矩阵（两行 I/Q）、`Q<<16|I` 的 packed int32、交错 int16，
或 Z 实波形；上传时统一转换为小端 `I0,Q0,I1,Q1,...` 并放入
`interleaved_512b` DDR 布局。上传不会自动打开输出，推荐顺序是
`download -> RFDC/NCO -> set_*_on_off -> arm -> trigger`。

旧 ez-Q 脚本中的 `slot` 参数仍被接受但不会写入 UDP。`MagicMock` 是
`unittest.mock.MagicMock` 的直接导出，`SimulatedDr47Device` 可用于没有板卡的
单元测试；模拟器同样不会伪造 DAQ/PUMP 成功。
