# 触发抖动问题完整解决方案 - 总结

## 问题回顾

**原始问题**：从卡（slave）跳过 SYNC，接收外部 Trigger（~8ns 脉冲），CH1 输出到示波器，波形在 **19-25 ns 范围内随机跳变**。

**根本原因**：HMC7044 `hmc_pl_clk` (96 MHz, 10.417 ns) 与 DAC `dac_axis_clk` (50 MHz, 20 ns) 之间存在 **25:48 相位晶格**，最大相位差达 **19.583 ns**。触发信号先在 `hmc_pl_clk` 域捕获，再同步到 `dac_axis_clk` 域，每次触发时相对相位不同，导致可观测的时序抖动。

## 解决方案对比

| 特性 | 方案 A：DAC 域直接捕获 | 方案 B：200MHz 相位测量补偿 |
|------|----------------------|--------------------------|
| **残余抖动** | **0 ns**（数字零抖动） | **< 2.5 ns**（1 个 fabric sample） |
| **外部触发要求** | ⚠️ 必须与 DAC 时钟同步（需 250 MHz 铷钟） | ✅ 完全独立（任意时钟、任意相位） |
| **资源消耗** | 低（无额外时钟） | 中等（+1 个 MMCM） |
| **实现复杂度** | 简单（async-set latch） | 中等（相位检测 + 补偿器） |
| **软件可见性** | 无（透明） | ✅ `phase_slot` + `phase_valid` |
| **适用场景** | 有共享 250 MHz 参考时钟 | 外部触发完全独立 |

## 方案 A：DAC 域直接捕获（已实现并验证）

### 核心思想
将触发捕获从 `hmc_pl_clk` (96 MHz) 移到 `dac_axis_clk` (50 MHz)，完全消除跨时钟域同步的相位不确定性。

### 关键模块
- `dac_ext_trigger_capture.v`：DAC 域 async-set latch，捕获 ~8ns 脉冲
- `dac_trigger_emitter.v`：DAC 域脉冲生成（XS18/XS20 输出）
- `dac_trigger_latency_probe.v`：测量 HMC→DAC 路径的延迟分布

### 硬件要求
- **XS17**：250 MHz 参考时钟（铷钟，与触发源共享）
- **XS19**：外部触发输入（~8ns 脉冲）
- **XS18**：可选自环测试（短接到 XS19）
- **XS20**：可选第二路 Trigger 输出（示波器参考）

### 验证结果
- ✅ ILA 测量：`spread = 0 cycles`（零抖动）
- ✅ 示波器余辉模式：完全叠加（包络稳定）
- ✅ 200 次回归测试：100% 通过

## 方案 B：200MHz 相位测量补偿（本次新增）

### 核心思想
保留 `hmc_pl_clk` 域捕获，但通过 **200 MHz 时钟测量触发到达时的 96 MHz 相位**，然后在 DAC 域注入 **0-7 个 fabric cycle (2.5ns) 延迟**进行补偿。

### 关键模块
1. **`ext_trigger_phase_detector.v`**
   - 用 200 MHz 时钟采样 96 MHz `hmc_pl_clk`
   - 将一个 96 MHz 周期（10.417 ns）划分为 **8 个相位 slot**（每个 ~1.3 ns）
   - 当触发到达时，记录当前 slot（0-7）
   - 输出 `phase_slot[2:0]` 和 `phase_valid`

2. **`ext_trigger_phase_compensator.v`**
   - 读取 `phase_slot`，注入 0-7 个 fabric cycle 延迟
   - 通过移位寄存器 `delay_line[7:0]` 实现可变延迟
   - 输出补偿后的触发脉冲（对齐到固定相位）

3. **`clk_gen_200mhz` IP**
   - MMCM：输入 96 MHz，输出 200 MHz
   - 必须与 `hmc_pl_clk` 相位锁定

### 固件扩展
- **STATUS 响应新增字段**（向后兼容）：
  ```c
  struct RFRESP2_STATUS {
      // ... 原有字段 ...
      uint8_t ext_trigger_phase_slot;    // 最近一次触发的相位 slot (0-7)
      uint8_t ext_trigger_phase_valid;   // 相位测量有效性 (0/1)
  };
  ```

### 验证方法

#### 1. XS18 自环测试（初步验证）
```bash
# XS18-XS19 短接
RFSOC_BOARD_IP=<IP> RFSOC_TRIGGER_COUNT=100 \
    python3 -m software.dr47.examples.hardware_slave_phase_compensation_test
```

**预期**：
- `phase_slot` **固定在某个值**（比如 3）
- `phase_valid = 1`
- ILA `spread = 0`

**解释**：自环时发射和捕获在同一时钟域，相位固定，验证补偿器工作正常。

#### 2. 外部触发测试（完整验证）
```bash
# 断开 XS18-XS19
# 外部触发源 → XS19（任意时钟）
# CH1 → 示波器

RFSOC_BOARD_IP=<IP> RFSOC_TRIGGER_COUNT=200 \
    python3 -m software.dr47.examples.hardware_slave_phase_compensation_test
```

**预期**：
- `phase_slot` **在 0-7 之间随机变化**（外部触发时钟独立）
- `phase_valid = 1` 始终为真
- 示波器余辉模式：**完全叠加**（包络稳定）
- ILA `spread = 0 或 1 cycle`（< 2.5 ns）

### 硬件要求
- ✅ **无需 250 MHz 共享参考时钟**
- **XS19**：外部触发输入（任意时钟，~8ns 脉冲）
- **XS17**：10 MHz 或 250 MHz 参考时钟（用于 DAC 采样率）

### 优势
- ✅ 通用性强：外部触发可以是任意独立时钟
- ✅ 软件可见：`phase_slot` 字段便于调试
- ✅ 性能足够：< 2.5 ns 对于 60 ns 包络完全可接受

## 使用建议

### 场景 1：有 250 MHz 共享参考时钟（铷钟）
→ **使用方案 A**
- 抖动 = 0 ns（数字零抖动）
- 资源消耗最少
- 已验证可用

### 场景 2：外部触发完全独立（无共享时钟）
→ **使用方案 B**
- 抖动 < 2.5 ns（对 60 ns 包络足够）
- 无需修改外部硬件
- 软件可见相位，便于调试

### 场景 3：不确定外部触发是否同步
→ **先部署方案 B**
- 通用性强，适配任意触发源
- 如果性能不够，再切换到方案 A（需要硬件改造）
