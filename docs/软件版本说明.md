# 47DR 软件使用说明

本文说明怎样安装驱动、第一次连上板卡并发出波形，文末是各版本的变更记录。每个接口的参数和
返回值见 [API 接口参考](API参考.md)，板卡的接口特性见[硬件指标](硬件指标.md)。

## 适用范围

- 主机：x86-64 Linux（glibc 2.17 及以上，例如 Ubuntu 20.04、RHEL 8 及更新的系统），
  Python 3.10–3.14，`numpy>=1.23`。
- 网卡：100G，QSFP28 接口。板卡是固定的 100G CAUI-4 加 RS-FEC，不做自协商；部分网卡要手动
  关闭自协商并指定 RS-FEC 才能建立链路。
- 100G 批量上传依赖 UDP 分段卸载（GSO，Linux 4.18 及以上的内核）。
- 驱动和板卡固件必须来自同一个发布版本。驱动连接时校验板卡的协议版本（RFCTRL2 v3）、
  build profile 和 Trigger path version，不匹配时抛出 `ProtocolVersionError`。

驱动版本以 `dr47.__version__` 为准，命令行 `dr47-network --version` 也可查看。

支持的功能：板卡发现和网络配置、RFDC 频率与通道开关、CH1–CH8 波形上传、有限次循环播放、
软件 `PLAY` 和 XS19 外部 Trigger 启动、不需要板卡的内存模拟器。不提供 TDC 校准和补偿接口。
软件测试不能代替示波器和频谱仪验收。

## 安装

SDK ZIP 解压后的内容：

| 路径 | 内容 |
| --- | --- |
| `packages/` | 驱动的二进制 wheel，每个 Python 版本一个 |
| `examples/` | 示例脚本 |
| `docs/` | 本文、API 接口参考、硬件指标 |
| `SHA256SUMS`、`MANIFEST.json` | 校验清单 |

在 SDK 目录下执行：

```bash
python -m pip install --find-links packages 47dr-driver
```

pip 会按当前 Python 版本选出对应的 wheel，并从软件源安装依赖 `numpy>=1.23`。主机不能联网时，
先在主机上装好 numpy，再加上 `--no-index` 执行同一条命令。100G 发送核心已经编译好随包提供，
主机不需要 C 编译器。

装完先跑模拟器示例检查安装，这一步不需要板卡，结尾应打印 `PASS`：

```bash
python -m dr47.examples.simulator_quickstart
dr47-network --version
```

## 第一次使用

### 1. 接线和上电

- XS17 接 250 MHz 参考时钟。不接参考，输出频率全部不对。
- 板卡的 QSFP28 网口接主机的 100G 网卡。
- 要观察的输出通道接示波器（50 Ω 端接）。使用外部触发时，触发源接 XS19。

板卡上电后从板载 flash 自启动，约 5–8 s 后可以通过网络访问，RFDC、DAC MTS 和 NCO 对齐在
这段时间内完成。

### 2. 找到板卡

每次上电，板卡都回到出厂的临时地址（169.254.x.x，由芯片序列号决定）。先给主机网卡配一个
同网段的地址，再广播发现板卡：

```bash
dr47-network prepare-interface --interface <网卡名> --source-ip 169.254.250.11/16   # 需要 root 权限
dr47-network discover --interface <网卡名> --source-ip 169.254.250.11
```

第一条命令等价于 `ip address replace 169.254.250.11/16 dev <网卡名>`，网卡上已经有这个地址时可以跳过。

`discover` 打印每块板卡的 `DEVICE_UID`、`CURRENT_IP` 和 `CURRENT_MAC`。记下 `CURRENT_IP`，
后面的脚本用它连接。没有发现板卡时，先确认链路已经建立（网卡的 RS-FEC 和自协商设置）以及
板卡上电已超过 8 s。

需要固定地址时用 `provision` 配置。配置的地址掉电后不保留，重新上电要再发现、再配置一次：

```bash
dr47-network provision --interface <网卡名> --source-ip 169.254.250.11 \
    --device-uid <DEVICE_UID> --ip 10.50.0.101
```

### 3. 运行示例

示例脚本在 SDK 的 `examples/` 目录，安装后也可以用 `python -m dr47.examples.<名称>` 运行。
每个脚本的配置都是文件顶部的常量：把板卡 IP（`BOARD_IP`）、主机网卡名（`UDP_INTERFACE`）和
源地址（`UDP_SOURCE_IP`）改成现场的值，然后不带参数运行，结尾打印 `PASS` 或 `FAIL`。

| 脚本 | 用途 | 需要 |
| --- | --- | --- |
| `simulator_quickstart.py` | 用内存模拟器走一遍上传和播放，检查安装 | 无 |
| `network_discovery_example.py` | 广播发现板卡并读取网络配置 | 板卡 |
| `waveform_software_play_example.py` | 上传一包高斯脉冲到 CH1/CH2，用软件 `PLAY` 发波 | 板卡、示波器 |
| `waveform_external_trigger_example.py` | 上传后等待 XS19 外部 Trigger 启动 | 板卡、示波器、触发源 |
| `waveform_bulk_upload_speed_example.py` | 经 100G 批量通路上传随机波形并测速，再完整播放一遍 | 板卡 |
| `waveform_100g_stress_example.py` | 把 100G 链路打满，报告带宽和丢包率，生成 HTML 报告 | 板卡 |

建议第一次先跑 `waveform_software_play_example.py`：示波器设为单次触发后运行脚本，应看到一包
高斯包络的正弦。接线和示波器设置写在脚本开头的说明里。

### 4. 写自己的程序

```python
import numpy as np
from dr47 import Dr47Device

iq = np.zeros(1024, dtype="<i2")          # I0,Q0,I1,Q1,...，400 MS/s
with Dr47Device(ip="169.254.5.248", udp_interface="enp1s0f0",
                udp_source_ip="169.254.250.11", batch_mode=True) as device:
    device.set_xy_target_frequency(1, 4.0)            # CH1 输出 4 GHz
    device.set_qc_on_off("xy", 1, "on")
    device.commit()                                   # 提交上面两项 RFDC 设置
    uploaded = device.upload_waveforms({1: iq}, loop_count=1)
    device.play(session=int(uploaded["session"]))     # 软件启动；也可以等 XS19 外部 Trigger
```

上传完成后板卡自动预取波形，准备好后进入 `WAIT_TRIGGER`，软件 `PLAY` 或 XS19 外部 Trigger
启动播放。外部 Trigger 只在 `WAIT_TRIGGER` 状态被接受，其他时刻到达的事件丢弃且不排队。
`waveform_status()` 返回当前状态、播放位置、underflow 计数和 Trigger 计数。

## 常用接口

| 类别 | 接口 | 作用 | 主要参数 |
| --- | --- | --- | --- |
| 连接 | `Dr47Device`、`connect()` | 创建并连接单板 | IP、端口、网卡 |
| 网络 | `discover_boards()` | 广播发现板卡 | 网卡、源 IP、广播地址 |
| 网络 | `provision_board()` | 设置固定 IP/MAC | 目标 IP、MAC、网关 |
| 状态 | `status()`、`capabilities` | 读取连接、RFDC、同步和播放状态 | `refresh` |
| RFDC | `set_xy_target_frequency()` | 根据目标 RF 频率计算 NCO 和 Nyquist zone | 通道、GHz、DAC 采样率 |
| RFDC | `set_xy_nco_frequency()` | 直接设置 NCO | 通道、NCO GHz |
| RFDC | `set_qc_on_off()` | 打开或关闭输出通道 | 类型、通道、`on/off` |
| RFDC | `commit()` | 提交暂存的 RFDC 配置 | 无 |
| 波形 | `upload_waveforms()` | 上传波形并提交 descriptor | 通道波形、掩码、循环次数、格式 |
| 播放 | `play()`、`pause()`、`stop()`、`abort()` | 软件启动、暂停、停止和取消 | session |
| 波形工具 | `make_iq_sine_interleaved()`、`make_iq_gaussian_sine_interleaved()` | 生成 IQ 波形 | 频率、幅度、采样率、时长 |

## 变更记录

### 第三版：单板清理和 100G 压测（驱动 0.4.0）

驱动 0.4.0 与同一版本的板卡固件配套使用。

- 驱动以二进制 wheel 交付（Python 3.10–3.14，x86-64 Linux）；100G 发送核心随包预编译，主机
  不再需要 C 编译器。
- 板卡从板载 flash 上电自启动，不需要 JTAG 加载。
- 新增 100G 压测脚本 `waveform_100g_stress_example.py`：用 4 个发送线程把链路打满，报告带宽、
  丢包率和丢包环节，判据是一帧不丢。脚本控制了发送端（限制 socket 发送缓冲、每一遍开始前等
  socket 排空），并检查链路确实被打满、主机自己没有丢帧，所以结果反映的是链路和板卡。每次
  跑完生成一份单文件 HTML 报告（含逐遍的速率和丢帧时间线）和同名的 JSON 原始数据。
- `dr47.bulk.BulkSender` 新增 `send_buffer_bytes` 参数（socket 发送缓冲，默认仍为 4 MiB）和
  `queued_bytes()`（socket 里还没发出去的数据量），供压测这类需要控制发送节奏的程序使用。
- 批量上传结果里的 `rx_dropped_full`、`rx_dropped_bad` 改为本次上传期间的增量；此前是板端
  上电以来的累计值，压测之后再上传会把压测丢的帧也算进去。
- 移除诊断快照：`read_diagnostics()`、`clear_diagnostics()` 和 `DiagnosticsSnapshot`。板端不再
  提供这两条命令；播放和 Trigger 的计数都在 `waveform_status()` 里。
- `DeviceCapabilities` 去掉恒为 0 的字段：`trigger_input_count`、`trigger_accepted_count`、
  `trigger_output_count`、`playback_admitted_count`、`playback_skipped_count`。
- `upload_waveforms()` 不再接受 `channel_sequences` 和未知关键字参数；移除 `upload_and_commit()`。
- 移除不再对应任何板端功能的协议辅助：`pack_rfctrl2_sync_epoch()`、`pack_rfctrl2_start_at()`、
  `pack_rfctrl2_diag_snapshot()`、`pack_rfctrl2_diag_control()`、`parse_rfctrl2_diagnostics_payload()`，
  以及 tiled 布局、旧批量包和指令流相关的常量与函数（`tiled_ddr_addr()`、
  `iter_max_length_udp_batches()`、`ezq_wave_to_packed_int32()` 等）。

### 第二版：触发链路和诊断改进

- 增加 RFCTRL2 v3 诊断快照 API：`read_diagnostics()` 和 `clear_diagnostics()`。
- HELLO/STATUS 增加 build identity、Trigger path version 和播放计数器校验。
- RFDC busy 时重复配置会先停止播放并重试，减少 `0x0006` 对应用的干扰。
- 删除未交付的 TDC 公共 API，避免安装包暴露不支持的功能。

### 第一版：SDK 发布基础

- 建立可发布的 Python SDK、wheel 和示例程序。
- 增加网络发现/配置、软件 PLAY、XS19 外部 Trigger 和模拟器流程。
- 统一 8 通道 WAVECTR0 波形上传、预取、状态查询和通道配置 API。
- 整理文档、测试目标和发布包校验清单。
