# 使用与测试指南

本文给出从安装到 slave 外部 Trigger 发波的当前操作流程。Python 函数见
[API 参考](API参考.md)，模拟输出指标见[硬件验收](硬件验收.md)。

## 1. 当前配置

| 项目 | 配置 |
| --- | --- |
| 外部参考 | XS17，250 MHz |
| RFCTRL2 UDP 端口 | 1234 |
| RFDC 复数 IQ 输入 | 400 MS/s |
| DAC sample rate | 6.4 GS/s |
| 调度时钟 | 50 MHz，时间参数按 20 ns 向上量化 |
| 单板测试 bitstream | `custom_xczu47dr_slave_trigout.bit` |
| 单板测试 firmware | `custom_xczu47dr_slave.elf` |

当前外部 Trigger 验收脚本是：

```text
software/dr47/examples/hardware_slave_bypass_external_trigger_test.py
```

## 2. 安装

源码开发环境：

```bash
cd xczu47dr-rfdc
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r software/requirements.txt
python -m pip install -e software/dr47
```

只使用驱动 SDK 时，从解压后的 SDK 目录安装 wheel：

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install ./packages/47dr_driver-0.1.0-py3-none-any.whl
python -m dr47.examples.simulator_quickstart
```

## 3. 单板连接

```text
XS17 <- 250 MHz 参考时钟
外部 Trigger 源 -> XS19
XS20 保持断开
CH1/CH2 -> 示波器或 50 ohm 负载
10G 网口 -> 主机或同一 VLAN 的交换机
```

`slave_trigout` 中 XS20 不是 SYNC 输入，因此脚本必须调用 `bypass_sync()`。
XS18 不参与本测试。

外部 Trigger 的间隔必须大于一组 burst 的播放时间，并留出播放器返回
`PREPARED` 的时间。Trigger 不会排队。

## 4. 烧写

使用仓库中已有产物：

```bash
JTAG_CABLE_SERIAL=<序列号> ./software/load_and_verify.sh slave_trigout
```

该命令加载：

```text
artifacts/custom_xczu47dr_slave_trigout.bit
artifacts/custom_xczu47dr_slave.elf
```

需要重新构建时：

```bash
source /tools/Xilinx/Vivado/2024.2/settings64.sh
source /tools/Xilinx/Vitis/2024.2/settings64.sh
make bitstream-slave-trigout
make firmware TARGET=custom_xczu47dr_slave
```

不同角色的 bitstream、XSA 和 ELF 不能混用。产物及 SHA-256 见
[`artifacts/README.md`](../artifacts/README.md)。

## 5. 配置网络

板卡重新烧写后通常回到 `169.254.x.y/16` 临时地址。先给主机 10G 网卡配置
同网段地址：

```bash
sudo ip link set enp1s0f0 up
sudo ip address replace 169.254.250.11/16 dev enp1s0f0
```

只读发现：

```bash
dr47-network discover \
  --interface enp1s0f0 \
  --source-ip 169.254.250.11 \
  --json
```

首次分配固定 IP：

```bash
dr47-network provision \
  --interface enp1s0f0 \
  --source-ip 169.254.250.11 \
  --device-uid <UID> \
  --ip 169.254.100.102 \
  --mac 02:00:00:2c:d6:91 \
  --json
```

配置前核对 UID、MAC 和当前 IP。旧 bitstream 可能存在相同 UID，驱动使用
`UID + MAC` 作为发现身份。每块板必须使用不同的 IP 和 MAC。

若 `NETWORK_APPLY` 返回 `0x0006`，说明板卡仍处于 ARM 或播放状态。先运行
`abort_playback()`，或重新运行测试脚本让其启动清理流程，再配置网络。

## 6. 测试顺序

### 6.1 无硬件自检

```bash
python -m dr47.examples.simulator_quickstart
```

预期输出包含 `driver simulation OK`。

### 6.2 只读发现

编辑 `network_discovery_example.py` 顶部的网卡和源 IP，然后运行：

```bash
python software/dr47/examples/network_discovery_example.py
```

SDK ZIP 用户运行 `python examples/network_discovery_example.py`。

### 6.3 软件 Trigger

编辑 `single_board_software_trigger_example.py` 顶部常量，并保持 XS18、XS19、
XS20 断开：

```bash
python software/dr47/examples/single_board_software_trigger_example.py
```

脚本会配置 CH1/CH2、上传一份波形、ARM，并发送一次软件 Trigger。终端应显示
`PASS`，示波器应看到设置数量的有限脉冲。

### 6.4 XS19 外部 Trigger

编辑 `hardware_slave_bypass_external_trigger_test.py` 顶部“用户配置”区域：

| 常量 | 含义 |
| --- | --- |
| `BOARD_IP` | 板卡当前 IP |
| `UDP_INTERFACE` / `UDP_SOURCE_IP` | 主机 10G 网卡和源 IP |
| `OUTPUT_CHANNELS` | 同时播放的通道 |
| `RF_FREQUENCY_GHZ` | 目标模拟 RF 频率 |
| `GAUSSIAN_DURATION_NS` | 单个高斯波形时间窗 |
| `GAUSSIAN_FWHM_NS` | 高斯包络半高全宽 |
| `FIRST_DELAY_NS` | Trigger 到第一个波形的延迟 |
| `PULSE_INTERVAL_NS` | 相邻波形起点间隔 |
| `PULSES_PER_TRIGGER` | 每次 Trigger 播放次数 |
| `TRIGGER_COUNT` | 本轮等待的外部 Trigger 数量 |

直接运行，不传命令行参数：

```bash
python software/dr47/examples/hardware_slave_bypass_external_trigger_test.py
```

正常流程为：

```text
连接 -> 清理旧状态 -> bypass SYNC -> 配置 RFDC
     -> 上传波形 -> ARM -> 等待 XS19 -> 完成后静音
```

通过条件：

- 终端输出 `PASS`；
- XS19 输入数等于接受数和 `TRIGGER_COUNT`；
- XS18 输出计数不增加；
- CH1/CH2 每次 Trigger 只输出设置数量的有限脉冲。

## 7. 常见问题

| 现象 | 处理 |
| --- | --- |
| 找不到板卡 | 检查网卡 `/16` 地址、链路、VLAN 广播、防火墙和 UDP 1234 |
| 新 IP 配置后超时 | 给主机增加新 IP 所在网段地址，再对新 IP 单播验证 |
| `NETWORK_APPLY 0x0006` | 停止播放并等待 `IDLE` 后重试 |
| `sync_link_ready=False` | 单板测试确认已调用 `bypass_sync()`；双板模式检查 XS20 |
| XS19 输入大于接受 | 外部 Trigger 太快，增大间隔 |
| 一次 Trigger 持续播放 | 检查是否烧写包含有限 repeat 修复的最新 bitstream |
| RF 频率错误 | 使用 `set_xy_target_frequency()`，并确认 XS17 为 250 MHz |
| 波形上传慢 | 使用 `bulk_upload=True` 并观察上传进度 |

脚本通过只说明数字控制和播放流程正常。频率、幅度、FWHM、通道时差和抖动仍需
按[硬件验收](硬件验收.md)使用仪器确认。
