# 使用与测试指南

本文是从安装到第一次发波的唯一操作说明。API 的函数签名和协议字段请看
[API 参考](API参考.md)，示波器验收项目请看[硬件验收](硬件验收.md)。

## 一、项目是什么

本项目由三部分组成：

- `hardware/`：Chisel 和 Vivado 硬件设计，生成 FPGA bitstream 和 XSA。
- `firmware/`：ZynqMP 裸机程序，启动时初始化时钟和 RFDC。
- `software/`：Python 驱动、波形工具和网页控制台，通过 UDP 控制 FPGA。

正常播放链路是“主机准备波形 -> UDP 写入板卡 DDR -> ARM -> Trigger -> DAC 输出”。
Python 不会在每个采样点之间参与播放；ARM 以后由 FPGA 本地数据通路连续取数。

## 二、安装软件环境

主机建议使用 Linux、Python 3.10 以上，并安装 Xilinx 2024.2 工具。开发环境可直接
使用仓库中的虚拟环境：

```bash
cd xczu47dr-rfdc
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r software/requirements.txt
python -m pip install -e software/dr47
```

`make test`、`make host` 等 Python 目标会自动优先使用仓库根目录下的 `.venv`
（`PYTHON` 变量可覆盖）。如果依赖没装齐，`make test` 会直接报出缺哪个包，而不是
抛出十几条 import 报错。

需要重新生成硬件时，再加载 Vivado、Vitis、Java 和 Mill：

```bash
source /tools/Xilinx/Vivado/2024.2/settings64.sh
source /tools/Xilinx/Vitis/2024.2/settings64.sh
```

只运行已有 bitstream 时不需要 Vivado；`make program` 直接使用 `artifacts/` 中的
`.bit`、`.xsa`、`.elf` 和 `psu_init.tcl`。

## 三、硬件连接

### 网络

当前推荐拓扑如下，三端口必须在同一 Access VLAN：

```text
主机 10G 网口 enp1s0f0 ─┬─ 交换机 ── 板卡 082
                         └─ 交换机 ── 板卡 081
```

交换机端口不能启用端口隔离、ACL、端口安全或广播风暴抑制；发现阶段必须允许
`169.254.255.255` 的二层广播。主机只用一个 10G 网口和一个发现地址。

### 时钟和双板同步

- 两块板的 XS17 接同一个 250 MHz 参考源（本分支 bitstream 不可接 10 MHz）。
- 主卡 XS20 接从卡 XS20，用于一次 SYNC。
- 主卡 XS18（`TRIG_1`）接从卡 XS19（`TRIG_2`），用于后续 Trigger。
- XS18 是输出，XS19 是输入；Type-C 不是同步链路。

主卡和从卡必须分别烧写对应角色的 bitstream，软件不能运行时改变 XS20 的电气方向。

## 四、烧写 bitstream 和固件

正式目标只有两个同步角色，另有一个独立带宽压力测试目标：

| 目标 | 用途 |
| --- | --- |
| `custom_xczu47dr_master` | XS20 输出，可作为同步主卡 |
| `custom_xczu47dr_slave` | XS20 输入，只能作为同步从卡 |
| `custom_xczu47dr_bw` | 独立 DDR 带宽测试，不用于正常 RFDC 播放 |

从仓库根目录构建：

```bash
# 只构建某个角色的硬件、XSA 和固件
make all TARGET=custom_xczu47dr_master
make all TARGET=custom_xczu47dr_slave

# 同时构建主卡和从卡 bitstream
make bitstream-dual
```

选择 JTAG 线缆并烧写：

```bash
JTAG_CABLE_SERIAL=<序列号> TARGET=custom_xczu47dr_master make program
JTAG_CABLE_SERIAL=<序列号> TARGET=custom_xczu47dr_slave make program
```

如果只使用已提交的产物，直接执行 `make program` 即可。主卡 bit、XSA、ELF 必须
成套使用，不能把 master 和 slave 的文件混搭。串口为 115200 波特率，可查看启动日志。

## 五、首次配置网络

板卡每次重新烧写后会回到 DNA 派生的 `169.254.x.y/16` 临时地址。先给主机网口配置
同网段地址（需要 sudo）：

```bash
sudo ip link set enp1s0f0 up
sudo ip address replace 169.254.250.11/16 dev enp1s0f0
ip route get 169.254.255.255
```

推荐用 NetworkManager 持久保存该地址：

```bash
nmcli connection show
sudo nmcli connection modify "<连接名>" +ipv4.addresses "169.254.250.11/16"
sudo nmcli connection up "<连接名>"
```

发现板卡（只读）：

```bash
dr47-network discover --interface enp1s0f0 \
  --source-ip 169.254.250.11 --json
```

输出中要核对 `device_uid`、MAC、临时 IP 和角色。旧 bitstream 可能让多块板的 UID
相同，驱动会用“UID + MAC”识别；不能只按交换机端口或 JTAG 序列号识别。

为每块板分配不同的正式 IP 和 MAC：

```bash
dr47-network provision --interface enp1s0f0 --source-ip 169.254.250.11 \
  --device-uid <UID> --ip 10.50.0.101 --mac 02:50:00:00:00:01
```

对另一块板使用不同地址，之后把主机正式地址加入同一网段，例如
`10.50.0.10/24`。重新烧写后不会保存板卡网络配置，需要重复“发现 -> 配置 -> 验证”。

## 六、运行测试脚本

正式板级入口都在 `software/dr47/examples/`，脚本顶部直接填写网卡、源地址、目标
IP、UID 和 MAC，不接受命令行网络参数。运行前先确认示波器探头已接到目标 DAC 差分
输出，并核对下面的板卡映射（JTAG 序列号与角色容易混淆，务必以 MAC/角色为准）：

| 角色 | JTAG serial | 正式 IP | MAC |
| --- | --- | --- | --- |
| master | `210512180082` | `169.254.100.101` | `02:00:00:ad:15:91` |
| slave | `210512180081` | `169.254.100.102` | `02:00:00:2c:d6:91` |

```bash
# 正式从卡：等待 XS20 SYNC，上传一次有限波形，之后每个 XS19 Trigger 播放一次
PYTHONPATH=software python -m dr47.examples.hardware_slave_wait_sync_trigger_test

# 正式主从：主卡发送一次 SYNC，之后每个主卡 Trigger 驱动两块板各播放一次
PYTHONPATH=software python -m dr47.examples.hardware_master_slave_sync_trigger_test

# 单块从卡 bypass：在代码顶部选择软件 Trigger 或 XS19 外部 Trigger
PYTHONPATH=software python -m dr47.examples.hardware_slave_bypass_trigger_test
```

推荐顺序是：先运行从卡 bypass 验证单板播放，再运行正式从卡等待外部 SYNC/Trigger，
最后运行主从同步。每个脚本失败时都会
尽力执行 `abort_mute()`；成功只代表数字控制路径走通，不代表频率、幅度或相位已经
通过仪器验收。

### ILA 上板抓取验证

`software/ila_gaussian_capture.py` 用于在 Vivado ILA 中确认主卡播放 0 Hz 基带
高斯包络时，真正进入 RFDC 的 `top_i/rfdc_ch1_tdata` 呈钟形变化，而不是历史故障中
的 `0x00010000...` 常数。它用 `top_i/pc_started` 作为触发源（不能用
`pc_trig_start`，那只是旧 GPIO 路径），并在抓取后把 256-bit 总线解码成 int16 做包络
校验。运行需要 Vivado 2024.2 和已启动的 `hw_server`：

```bash
cd xczu47dr-rfdc
source /home/yk/Vivado/2024.2/settings64.sh
PYTHONPATH=software .venv/bin/python -m ila_gaussian_capture
```

抓取结果和日志写入 `ila_gaussian_reports/`。脚本网络、JTAG、波形参数都在文件顶部以
模块常量定义，不接受命令行参数；目标板卡默认是 master（JTAG `210512180082`）。

### 同步时钟域说明

主从同步使用 XS17 共同的 250 MHz 参考，经 HMC7044 的 R1=25 分频进入 10 MHz PLL1
PFD，锁定 VCO 3072 MHz，再产生约 96 MHz 的 `PL_CLK`（3072/32）、128 MHz 的 RFDC
参考（3072/24）和 2 MHz 的 SYSREF。RFDC 由 128 MHz 倍频到 6.4 GS/s，DAC 用户 AXIS
时钟为 50 MHz（6400/128），一个 AXIS beat = 20 ns。

**外部 Trigger 不再走 `PL_CLK` 域。** 早期版本把 XS19 的捕获和 XS18/XS20 的生成都
放在 HMC `PL_CLK` 域，那是 Trigger→RF 抖动的主要来源：`PL_CLK`（96 MHz）与
`dac_axis_clk`（50 MHz）同源于 HMC7044 的 VCO，周期比恰为 25:48，因此

    gcd(20 ns, 125/12 ns) = 5/12 ns = 0.41667 ns，跨度 19.583 ns

`PL_CLK` 的边沿会落在 20 ns DAC 周期内的 48 个相位上，即使 XS19 本身完全干净，启动
时刻也会铺满约 19.6 ns。这个相位格由 HMC7044 内部分频比决定，与 XS17 输入是 10 MHz
还是 250 MHz 无关，因此本分支同样适用。

当前实现：

| 环节 | 时钟域 | 模块 |
|---|---|---|
| XS19 外部 Trigger 捕获 | `dac_axis_clk` | `dac_ext_trigger_capture`（异步锁存，可接住 ~8 ns 窄脉冲） |
| 启动调度 | `dac_axis_clk` | `dac_trigger_scheduler` |
| XS18/XS20 Trigger 输出 | `hmc_pl_clk`，或 `dac_axis_clk`（`TRIG_EMIT_DAC=1`） | `sync_trigger_link` / `dac_trigger_emitter` |
| XS20 SYNC | `hmc_pl_clk` | `sync_trigger_link`（`XS20_TRIG_OUT=0` 时） |
| PS 命令与状态跨域 | `pl_clk` / `ddr4_ui_clk` | 只做命令与状态，不在物理事件路径上 |

`custom_xczu47dr_slave_trigout` 这个 target 把 `XS20_TRIG_OUT=1` 和
`TRIG_EMIT_DAC=1` 一起打开：XS20 复用为第二路 Trigger 输出给示波器做时间基准，且
基准与 RF 启动同域。该构建没有 SYNC 输入，只能用 bypass 模式。

抖动实测值用以下脚本从 ILA 读取（不依赖示波器）：

```bash
source /home/yk/Vivado/2024.2/settings64.sh
.venv/bin/python software/trigger_latency_report.py --jtag-serial 210512180082 \
  --ltx artifacts/custom_xczu47dr_slave_trigout.ltx
```

HMC 域事件 tick 仍可单独抓取：

```bash
ILA_CAPTURE_ROLE=master PYTHONPATH=software .venv/bin/python software/ila_hmc_event_capture.py
```

脚本会导出 `hmc_event_tick`、`sync_event_tick`、`trigger_capture_tick` 和
`trigger_launch_tick`，用于定位事件链。

**外部 Trigger 的残余抖动取决于源的沿栅格**，不取决于捕获路径。本分支的目标配置是
Trigger 源与 XS17 共用同一个 250 MHz 铷钟，因此沿落在 4 ns 栅格上：20 ns 与 4 ns 的
比值是 5，抖动为 5 个相位、16 ns。要继续往下压：

| 补偿粒度 | 残余抖动 |
|---|---|
| 只对齐 AXIS beat（当前） | 16 ns |
| beat 内 fabric 样点偏移（2.5 ns） | 2.0 ns |
| DAC 输出样点偏移（156.25 ps） | 0.125 ns |
| 源沿落在 20 ns 整数倍栅格上 | 0（无需补偿逻辑） |

参考源换成 250 MHz 还有一个与抖动无关的好处：倍频到 6.4 GHz 只有 25.6 倍，参考相位
噪声被放大 28 dB；10 MHz 是 640 倍、56 dB。

### 用示波器测抖动时的注意事项

数字通路的抖动已经低于 2.5 ns 的 fabric 样点粒度，因此示波器上看到的百 ps 级余辉
宽度基本由测量方法决定，不是启动抖动。踩过的三个坑：

- **不要在慢包络的半高点上测。** 60 ns 高斯包络在半高点的斜率约 0.023/ns，幅度噪声
  会按 1/斜率 放大成时间噪声：0.5% 噪声 = 216 ps，1% = 433 ps。同样的噪声改测
  1 GHz 载波零交叉（斜率 6.28/ns）只有 0.8 ps / 1.6 ps，精度差 270 倍。示波器上
  看到的 ~300 ps 只对应约 0.7% 幅度噪声，属于正常本底。
- **`:TRIGger:SWEep` 必须设成 `NORMal`。** `AUTO` 在没有触发时自由扫，会把无关扫描
  线画进余辉，直接虚增表观抖动。
- **采样率要足够。** 4 GSa/s = 250 ps/点，此时 300 ps 只有 1.2 个采样间隔，读数由
  sin(x)/x 插值误差主导。测 ps 级要把时基拉到最小、采样率拉满，并用抖动直方图的
  标准差读数，而不是看余辉包络的峰峰宽度。

## 七、最小 Python 控制示例

```python
from dr47 import Dr47Device, make_trigger_sequence

with Dr47Device(
    ip="10.50.0.101", port=1234,
    udp_interface="enp1s0f0", udp_source_ip="10.50.0.10",
) as board:
    board.set_xy_nco_frequency(1, 1.0)  # 高层频率单位为 GHz
    board.set_qc_on_off("xy", 1, "on")
    board.upload_waveforms({1: iq}, {1: make_trigger_sequence(len(iq))},
                           wave_formats={1: "iq_matrix"}, auto_start=False)
    board.arm(channel_mask=0x01)
    board.trigger()       # 本地 UDP Trigger，不会驱动 XS18
    board.abort_mute()    # 测试结束关闭输出
```

RFDC 的 IQ 输入是 400 MS/s，基带范围约为 `-200 MHz..+200 MHz`；更高的射频载波
应由 NCO 产生，上传的 IQ 通常只放低频或直流包络。完整接口见 [API 参考](API参考.md)。

## 八、找不到板卡时按这个顺序查

1. `ip -brief address` 确认 `enp1s0f0` 已启用并有正确的 `169.254.250.11/16`。
2. `ethtool enp1s0f0` 确认 `Link detected: yes` 和预期速率。
3. `tcpdump -ni enp1s0f0 udp port 1234` 确认主机发出了广播。
4. 交换机确认主机、两块板在同一 Access VLAN，关闭隔离和广播抑制。
5. 串口确认板卡已启动 RFCTRL2；若同一临时 IP 出现两块板，先逐块隔离并分配正式 IP。
6. 单播验证：`dr47-network status --interface enp1s0f0 --ip <正式IP>`。

Linux 原始 UDP 绑定需要 `CAP_NET_RAW`，自动配置网卡地址还需要 `CAP_NET_ADMIN`。
普通终端可用 `sudo` 运行相关命令；网页服务的 systemd 权限见[网页部署说明](../software/网页部署说明.md)。
